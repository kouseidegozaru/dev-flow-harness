# デザイン指針 (screen-designer 用)

画面デザインを作る・直すときに必ず従う指針。目的は「それらしく見える」ことではなく、
**利用者が迷わず目的を果たせ、そのまま実装の手本にできる画面** を作ること。

指針より優先するもの: (1) ユーザーの修正指示 (2) `design-spec.md` の作成指示 (トーン・既存のデザインシステム) (3) この指針。
既存のデザインシステム・ブランド指定 (色・書体・部品) があれば、この指針の既定値より必ずそちらを使う。

---

## 1. 描く前に決めること

描き始める前に、次を自分の中で決める (報告の `ASSUMPTIONS` に要点を書く)。

1. **画面の目的を 1 文で**: 「利用者が〜するための画面」。目的に効かない要素は置かない
2. **主要な操作を 1 つ**: 画面ごとに最も重要な操作 (主ボタン) は 1 つだけ。2 つ以上あると視線が割れる
3. **情報の優先度を 3 段階に分ける**: 1 位 (最初に目に入るべきもの) / 2 位 (判断に使う) / 3 位 (必要なら見る)。
   1 位は大きさ・太さ・位置で目立たせ、3 位は小さく・薄くする。**全部を同じ強さにしない**
4. **トーンを 1〜2 語で**: 例「落ち着いた業務用」「軽快な個人向け」。以降の配色・書体・余白・文言はこの語に合わせる
5. **情報密度**: 業務系・管理画面は高密度 (行の高さ 36〜40px、余白小さめ)、個人向け・初回利用が多い画面は低密度 (余白大きめ)

## 2. 基盤 (デザイントークン)

値は CSS 変数として 1 か所 (共通 CSS) に定義し、各ページはそれを参照する。**トークン以外の半端な値 (13px、7px、#3a3b3c など) を直接書かない。**

### 余白 (4px 基準)

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96` だけを使う。

- 関係の強い要素ほど近く、弱いほど遠くする (近接)。**グループ分けは線より余白で行う**
- 要素内の余白 < 要素間の余白 < セクション間の余白 の順に大きくする (例 8 / 16 / 32)
- 同じ種類の間隔は画面全体で同じ値にそろえる (反復)

### 文字

| 役割 | サイズ | 太さ | 行の高さ |
|------|--------|------|----------|
| 補足・注記 | 12px | 400 | 1.5 |
| 本文 (小) ・表 | 14px | 400 | 1.6 |
| 本文 | 16px | 400 | 1.7 |
| 小見出し | 18〜20px | 600 | 1.4 |
| 見出し | 24px | 600〜700 | 1.3 |
| ページタイトル | 28〜32px | 700 | 1.25 |

- サイズは上の段階だけを使う。1 画面で使うサイズは 4 種類程度までに抑える
- 太さは 400 と 600 (見出しのみ 700) の 2〜3 種類まで
- 1 行の長さは、和文で 30〜40 字、欧文で 45〜75 字を目安に最大幅を決める
- 数字を縦にそろえる箇所 (表、金額、件数) は `font-variant-numeric: tabular-nums`。金額・数量は右揃え
- 書体はシステムフォントのスタックを基本にする:
  - 和文を含む: `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", system-ui, sans-serif`
  - 等幅: `ui-monospace, "Cascadia Mono", "Consolas", "SFMono-Regular", monospace`
- 書体は最大 2 種類 (本文用と、必要なら見出し用または等幅)

### 色

- **中立色 (グレー) を 8〜10 段**: 背景・面・境界線・補足文字・本文文字に使う。純粋な灰色より、主色の色味をわずかに混ぜた灰色のほうがまとまる
- **主色 (ブランド色) 1 色**: 主ボタン・リンク・選択中・フォーカスに使う。面積は画面の 1 割以下
- **意味の色**: 成功 (緑系)・注意 (黄〜橙系)・エラー (赤系)・情報 (青系)。それぞれ「文字用の濃い色」と「背景用の淡い色」の 2 段を用意する
- 配分の目安は 中立色 6 : 面・補助 3 : 主色 1
- コントラスト比: 本文の文字は背景に対して **4.5:1 以上**、18px 以上の太字・大きな文字は 3:1 以上、ボタンの枠や入力欄の境界などの部品も 3:1 以上
- **色だけで区別しない**: エラーは色に加えてアイコンか文言、選択中は色に加えて太さ・チェック・形で示す
- 黒は `#000` ではなく中立色の最も濃い段 (例 `#1f2328` 前後) を使う

### 形

- 角丸は 2〜3 種類 (例 小 4px: 入力欄・ボタン / 中 8px: カード / 全丸: タグ・アバター)
- 影は 2 段まで (浮いている要素: メニュー・モーダル)。平面の要素 (カード一覧など) は影ではなく境界線か背景色の差で区切る
- 境界線は 1px、中立色の淡い段

## 3. レイアウト

- **整列**: すべての要素を少数の縦の基準線にそろえる。左揃えを基本にし、中央揃えは短い見出し・空状態・ダイアログのボタン程度にとどめる。長文を中央揃えにしない
- **グリッド**: デスクトップは 12 列 (余白 24px)、タブレット 8 列、モバイル 4 列を目安に。コンテンツの最大幅を決める (本文中心なら 720px 前後、一覧・管理画面なら 1200〜1440px)
- **視線の流れ**: 上から下、左から右。ページタイトル → 主要な情報 → 主操作 の順に目が動くように配置する
- **主操作の位置**: フォームは入力欄の下 (左揃え、または右揃えで統一)、一覧画面はタイトルの右、ダイアログは右下。画面間で同じ種類の操作は同じ位置に置く
- 画面の幅: 対象端末に合わせて描く (デスクトップ 1280〜1440px、モバイル 390px)。レスポンシブが要件にある場合は両方の幅を示す

## 4. 部品

| 部品 | 決まりごと |
|------|------------|
| ボタン | 階層は 主 (塗り、1 画面 1 つ) / 副 (枠線) / 控えめ (文字のみ) / 危険 (赤、削除など)。高さ 36〜44px、クリック・タップ領域は 44×44px 以上。ラベルは動詞で具体的に (「保存」「タスクを追加」。「OK」「はい」は避ける) |
| 入力欄 | ラベルは入力欄の上に常に表示する (プレースホルダをラベルの代わりにしない)。必須・任意の表示を統一する。エラーは入力欄の下に、アイコン + 何が悪くどう直すかを書く。入力欄の幅は想定する内容の長さに合わせる |
| 表・一覧 | 列見出しを付ける。数値は右揃え、文字は左揃え。行の区切りは淡い線か余白 (しま模様は多用しない)。操作列は右端。並び順と件数を示す |
| カード | 同じ種類の情報を並べるときだけ使う。すべてをカードで囲まない |
| ナビゲーション | 現在地を色以外の手がかり (太字、下線、印) でも示す |
| ダイアログ | 取り消せない操作の確認に使う。何が起きるかを具体的に書き、危険な操作のボタンは危険色にし、既定のフォーカスは安全な側に置く |
| 通知 (トースト) | 操作の結果を短く知らせる。重要な失敗はトーストで済ませず、画面内に残す |
| アイコン | 線の太さと大きさを統一した 1 系統 (インライン SVG)。意味が曖昧なアイコンには文字ラベルを添える。アイコンだけのボタンには `aria-label` |

## 5. 状態

画面仕様の状態 (通常・空・エラー・ローディング など) はすべて描く。どれも「ついで」ではなく、1 つの画面として作り込む。

| 状態 | 描き方 |
|------|--------|
| 通常 | 現実的な件数・長さのデータで描く。**最長の文字列、桁の多い数値** も 1 件は混ぜ、折り返し・切り詰めの見え方を示す |
| 空 | 何もない理由と、次にとる行動 (主ボタン) を示す。イラストは不要、あっても小さく |
| エラー | 何が起きたか・利用者に何ができるか (再試行、入力の修正、問い合わせ先) を平易に書く。利用者を責めない |
| ローディング | 1 秒以上かかる所だけ。レイアウトの形を保つスケルトン表示を基本にする |
| 部品の状態 | 押せる要素には hover・フォーカス (キーボード操作時に見える枠。消さない)・押下中・無効 を定義する。無効のボタンには理由が分かる手がかりを添える |

## 6. 文言

- 画面仕様にある文言は一字一句そのまま使う (screen-designer の規則)
- 仕様にない文言を仮に入れる場合: 敬体 (です・ます) か常体かを画面全体でそろえる。短く、具体的に。専門用語より利用者の言葉
- 日付・時刻・数値・通貨の書式を画面全体でそろえる (例 `2026/09/25 14:05`、`1,234 件`)

## 7. 避けること (いかにも自動生成に見える要素)

- 意味のないグラデーション背景、紫〜青の派手なグラデーション
- 強すぎる影・大きすぎる角丸・すりガラス効果の多用
- 絵文字をアイコン代わりに使うこと
- 左端に太い色帯を付けたカードの乱用、すべてをカードで囲むこと
- 装飾だけのイラスト・写真風プレースホルダ、中身のない「ヒーロー」領域
- すべての要素が同じ強さで並ぶ画面 (優先度がない)
- 実在しない数値の統計・グラフ・ロゴ (仕様にない情報を作らない。必要なら `[件数]` のような明示的なプレースホルダ)
- lorem ipsum、「テキストテキスト」

## 8. CLI・端末アプリ

- 等幅フォント、端末ウィンドウ風の枠 (タイトルバー + 背景色) の中に、プロンプト・入力したコマンド・出力をそのまま描く
- 出力の色は、仕様で色付けが決まっている場合だけ使う。仕様で色を付けない出力に色を付けない (見やすさのための色は枠やプロンプトだけ)
- 1 画面に複数の実行例を並べてよい (例: 正常 → エラーの順に実行した様子)

## 9. 仕上げの確認 (報告の前に必ず行う)

作ったすべてのページについて、次を 1 つずつ確認し、満たさないものは直してから報告する。報告の `CHECKLIST` に結果を書く。

- [ ] 画面の目的・主操作・情報の優先度 (1 章) が見た目に表れている (主操作は 1 つだけ目立つ)
- [ ] 余白・文字サイズ・色・角丸がトークンの値だけでできている (半端な値の直書きがない)
- [ ] 要素が少数の基準線にそろっている。同じ種類の間隔が同じ値
- [ ] 文字のコントラスト比が基準を満たす。色だけで区別している所がない
- [ ] 画面仕様のすべての状態があり、空・エラーも作り込まれている。最長の文字列・大きい数値の例がある
- [ ] 押せる要素にフォーカスの見た目がある。ボタン・リンク・入力欄が正しい要素 (`<button>`・`<a>`・`<label>`) で書かれている
- [ ] 画面間で、同じ種類の部品・操作の位置・文言の書き方がそろっている
- [ ] 7 章の「避けること」に当たる要素がない
- [ ] 画面仕様の要素に `data-id`、状態に `data-state-id` と `id` が付いている。オフラインで開ける
