# 規約

## 1. ディレクトリ構成

```
<ルート>/
  src/...
  tests/...
```

`.gitignore` にビルド成果物とテスト結果ファイル (例: `bin/`、`obj/`、`TestResults/`) を必ず入れる
(`devflow-commit.ps1` は `git add -A` でコミットするため)。

## 2. 命名

| 対象 | 規則 | 例 |
|------|------|----|
| ファイル | | |
| 型・クラス | | |
| 関数・メソッド | | |
| 変数・定数 | | |

## 3. コーディング規約

<書式 (フォーマッタと設定)、null の扱い、例外の使い方、ログ、コメント、依存の向き>

## 4. テスト方針

- 単体テストの範囲: <どの層をどう切り離すか、テストダブルの方針>
- 結合テストの範囲: <ファイル・DB・プロセスを実際に使うテスト>
- テストデータ: <固定値 / ファクトリ / 一時ディレクトリの扱い>
- 1 テスト 1 観点。テストケースはタスクファイルの「テストケース」節の値をそのまま使う

## 5. テストへの ID 埋め込み形式

テスト名 (結果ファイルに出る名前) の先頭に、検証する ID を `[ID]` の形で並べる。

```<言語>
// 例 (xUnit): [Fact(DisplayName = "[REQ-TODO-001][IF-store-002] 空のストアに追加すると件数が1になる")]
```

- 結果ファイル: <JUnit XML / TRX>、出力先: <パス> (`.devflow/config.json` の `test.resultGlobs` と一致させる)
- 確認済み: <YYYY-MM-DD にサンプルテストで結果ファイルに ID が出ることを確認>

## 7. コミット規約

- Red: `test(<TASK-ID>): ...` / Green: `feat(<TASK-ID>): ...` / Refactor: `refactor(<TASK-ID>): ...`
- コミットは `scripts/devflow-commit.ps1` で行う (テストの成否を機械的に確認する)
