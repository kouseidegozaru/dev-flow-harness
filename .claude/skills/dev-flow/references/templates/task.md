## 参照すべき設計

実装者はここで指した節と conventions.md だけで実装できること。実装者とレビュー担当は、`devflow-state.ps1 task-context <TASK-ID>` が
この節から切り出した読み物 (タスクファイル + 指した節 + ID の定義行) だけを読む。書き方 (機械的に切り出すための決まり):

- 1 行に 1 ファイル。ファイルはバッククォートで囲んだ `docs/` からのパス (`.md` か画面デザインの `.html`)
- 節は見出しの文字列を「」で囲んで書く (「」は見出しにだけ使う。表の行や語句を「」で囲まない)。見出しが見つからなければ trace が TASK-REF-NOT-FOUND にする
- ID をそのまま書くと、その ID の定義行 (表の見出し行と合わせて) と、ID で始まる見出しの節 (「IF-x-001 の詳細」など) が切り出される
- 画面デザインの `.html` は、状態・要素の ID (`SCR-...-S01` など、`data-state-id` / `data-id` の値) を書くと、その要素だけが切り出される
  (どの場合も svg の中身と script は除かれる)。デザインの HTML は大きいので、このタスクで作る状態の ID を書く
- 「」も ID もない行は、ファイル全体を読ませる。大きいファイルには使わない (読み物は `taskContextBudgetKB` 以内)

- `docs/04-detailed-design/modules/<module>.md` の「<見出し>」 IF-<module>-001, BR-<...>-001
- `docs/04-detailed-design/api/<res>.md` の「<見出し>」 VAL-<...>-001, EC-<...>
- `docs/03-basic-design/designs/SCR-<NNN>.html` の SCR-<NNN>-S01, SCR-<NNN>-S02

## 作成・変更するファイル

パスだけをバッククォートで囲む (シグネチャやディレクトリ名・コード中の名前は囲まない。囲んだパスは完了時に存在が確かめられる)。
新しく作るファイルは、パスの後ろに「新規」と書く (他のタスクが新規に作るファイルを使うなら、そのタスクを依存に入れる。trace が確かめる)。

- `src/<...>` (新規 / 変更: <何を足すか 1 行>)
- `tests/<...>` (新規)

## テストケース

担当する `test` の ID ごとに 1 つ以上。入力と期待結果を具体的な値で書く。
期待結果が設計の文言・書式そのものなら、写さずに参照してよい (例:「IF-cli-004 の『使い方の表示』の全文」)。
非機能要件 (NFR) の ID は、その「測定条件」(データ量・環境) を前提・入力に書く。

| # | 検証する ID | 前提・入力 | 期待結果 |
|---|-------------|------------|----------|
| 1 | REQ-...-001, IF-...-001 | <具体的な値> | <具体的な値・文言、または設計の参照> |
